# hxyfront-62011 马术赛事放行台

在蹄铁师修蹄档案之上，打通**马匹档案 / 比赛报名 / 复查提醒 / 蹄铁更换历史**的赛前排放行工作台，
模拟「场边断网登记 + 办公室同时改表 + 回网合并」的完整一致性流程。

## 核心规则

1. **断网记录带报名版本**：现场每条登记都冻结当时的 `报名版本 / 禁用蹄铁清单版本 / 复查日期版本` 与报名内容快照，离线期间持续可登记。
2. **回网合并，同版本两边改过 → 两份待裁决**：现场记录基于的报名版本与服务器不一致时，现场副本（后到）**不覆盖**办公室数据，两份同时进入冲突箱，由赛事秘书人工裁决（采用现场版会按最新依据重新校验；采用办公室版则现场记录作废、要求重检）。
3. **禁用清单 / 复查日期一变，放行结论立即失效**：
   - 禁用蹄铁清单版本推进，使用「禁用状态发生翻转」蹄铁的放行结论即时标记失效；
   - 某匹马复查日期变更，该马全部有效结论即时失效。
   - 断网期间依据发生变化的记录，回网落账即为「失效 · 要求重检」。
4. **现场批次可重试，重传幂等**：以 `batchId` 为幂等键；请求丢失可原样重试（服务器无副作用）；回执丢失后重传只回放首次结果，**不重复生成放行记录、不重复写蹄铁历史**。记录级另有 `clientId` 去重。

## 页面

- **放行台**：一屏串联马匹档案、报名、蹄铁历史、复查提醒、最新放行结论与版本链，支持临期复查 / 异常步态 / 失效等筛选；点击结论查看携带版本与四蹄对比详情。
- **场边登记（蹄铁师）**：断网可登记蹄况（左前/右前/左后/右后）、蹄铁、钉位、复查日期、异常步态与照片备注；系统按缓存快照建议放行结论，可人工覆盖；写入「编辑中 → 封批」现场批次。
- **办公室（赛事秘书）**：改报名（版本 +1）、维护禁用蹄铁清单、调整复查日期。
- **冲突裁决**：左右对比现场副本与办公室当前报名（字段级 diff），双按钮裁决。
- **同步批次**：单批重试 / 一键合并全部待同步批次；可注入「请求丢失」「回执丢失」故障观察幂等行为；底部展示服务器幂等台账。

顶栏可切换 **在线 / 断网**、注入同步故障、重置演示。数据存于 localStorage，刷新不丢。

## 技术栈

React 19 + Vite + TypeScript，无额外状态库（`useSyncExternalStore` 订阅两个内存 store）。

```bash
npm install
npm run dev      # http://localhost:62011
npm run build
```

## 快速验证路径

1. 场边登记页保存一条 → 封批；
2. 顶栏切「断网」；
3. 办公室页修改同一报名（或勾选禁用该马所用蹄铁 / 修改复查日期）；
4. 回网 → 「立即合并」：
   - 报名改过 → 冲突裁决页出现两份待裁决；
   - 清单/复查改过 → 放行台该马结论变「结论失效·需重检」；
5. 同步批次页选「故障：回执丢失」后连续重试，可见「幂等回放」且台账/蹄铁历史不重复增加。
